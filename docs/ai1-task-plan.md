## 진행 원칙

- 검증되지 않은 자료는 답변 근거로 사용하지 않고, 필요하면 상담사 이관 경로로 보낸다.
- 게시·수정일과 시행일을 혼용하지 않는다.
- 정책 변경은 문서 단위가 아니라 `claimKey` 단위로 대체 관계를 기록한다.
- 시연 대본 ID로 검색을 분기하지 않고 문의·관할·유효기간·근거 상태로 판정한다.

## 현재 차단 사항과 다음 행동

1. T012의 해시 불일치를 해결한다. 원인은 `core.autocrlf=true` 환경에서 `data/sources/**`에 `-text` 속성이 없어 커밋 시 CRLF→LF, 체크아웃 시 LF→CRLF로 바이트가 바뀐 것이다. 6건 대조 결과 smartclean은 커밋 blob(LF), 120dasan은 작업 트리(CRLF)와 일치했지만, 나머지 4건은 어느 쪽과도 일치하지 않는다. 원본의 혼합 줄바꿈 바이트가 저장소에서 사라졌으므로 해시 기준을 확인하는 것만으로는 복구할 수 없다.
   - 먼저 `.gitattributes`에 `data/sources/** -text`를 추가해 스냅샷을 바이트 그대로 보존한다.
   - 그다음 핵심 원문을 재수집하고 `data/evidence-log.jsonl`에 새 항목을 추가한다. 기존 줄은 덮어쓰지 않는다.
   - 커밋 0f371b2의 `result: approved`, `verifiedFlag: true` 기록은 재수집한 해시로 다시 확인하기 전까지 시연 근거로 확정하지 않는다.
2. T012가 끝나면 T013에서 데이터 검증·corpus 빌드 스크립트를 구현한다.
3. T014에서 T011 근거 자격 판정을 검색 순위·색인과 연결하고 독립 평가를 실행한다.
4. T039 완료 뒤 AI2·AI3 통합 선행 작업(T018, T025)을 기다려 T046 일반화 검증을 수행한다.

## 검증 명령

```powershell
Set-Location frontend
npm test
npm run lint
```

현재 단위 테스트(16 pass, 3 todo)와 lint는 통과한다. T013 전에는 `npm run data:validate`와 `npm run data:build`가 가리키는 `frontend/scripts/*`가 없으므로 성공 검증 대상으로 간주하지 않고, CI에서도 실행하지 않는다.
