# Quickstart — 구현 후 실행·검증 가이드

현재는 계획 단계다. package.json·스크립트·앱·테스트는 아직 없으므로 아래 명령은 구현 단계에서 제공할 인터페이스다. 이 문서 작성으로 실행 성공을 의미하지 않는다.

## 1. 사전 확인

- Node.js 22 LTS 이상, npm, Chrome, 마이크, LLM 네트워크·유효 API 키.
- 프로젝트 루트에서 실행. .env.local에 OPENAI_API_KEY, OPENAI_MODEL, CONSOLE_TOKEN, DATA_DIR=data/snapshots 설정. 실제 비밀값은 Git·로그·프런트 번들에 넣지 않는다.
- 모델은 서버 어댑터의 structured output 사전 시험 통과 ID 사용. 기본값을 임의 추측하지 않고 미설정이면 시작 전 실패.
- DEMO_MODE=live, 시연 기준은 DEMO_DATE=2026-11-21로 명시. 테스트 fixture는 버전된 corpus 사용. 모델/음성 비동작 시 화면 fixture와 녹화 백업은 구분.
- 제출 환경은 HTTPS의 단일 장기 실행 Node 서버+지속 디스크다. localhost는 개발·백업용. 가상 데이터만 사용하고 세션 토큰·콘솔 인증·최대 세션/요청 제한을 적용한다. 배포 계정·주소·환경변수는 구현 착수 시 확인하며 현재 확보했다고 가정하지 않는다.

## 2. 구현할 명령

```powershell
npm ci
npm run data:validate
npm run data:build
npm run test
npm run build
npm start -- --hostname 127.0.0.1
```

첫 구현에서 lockfile을 생성한 뒤부터 npm ci를 사용한다. 개발은 npm run dev. 별도 터미널에서 npm run test:e2e (Playwright 브라우저 준비 후), npm run test:golden, npm run test:generalization을 실행한다.

data:validate는 출처/관할/날짜/대체 관계/미검증 answerEligible 위반에서 실패해야 한다. data:build는 원본을 덮어쓰지 않고 버전된 색인을 만든다. test:generalization은 테스트 결과 파일에 caseId·예상/실제·근거·규칙을 기록한다.

## 3. 화면 검증

시민 http://localhost:3000, 콘솔 http://localhost:3000/console. 콘솔 토큰은 로그인 입력으로만 받아 메모리에 유지하고 URL에 넣지 않는다.

1. 냉장고 질문에서 자치구 질문, 마포구 안내, 부품 훼손·용량 미확인 조건을 확인한다. 종료하면 대기열이 생기지 않는다.
2. 후불카드·페이백 문의는 최신 일정·신청 시기·개인 조회 불가·요약 승인·콘솔 수신을 확인한다. 두 변경 이력과 티머니 우선 후보를 확인한다.
3. 수도 문의는 근거 없음 1회 보완 후 사람 요청에 즉시 요약 확인, 불만 추정·부서 미생성·원문 전달을 확인한다. 검증용 corpus에는 수도 요금 청크를 넣지 않는다.
4. 두 화면 모두 모의 상담 표기, 음성/텍스트 대체, 한 질문, 쉬운 한국어, 색상 외 상태 설명을 확인한다. 팀 외 1명의 기본 사용성 검토를 기록한다.

## 4. 일반화·정책 검증

- SC-013 독립 15문항(새 근거 질문 5·표현/순서 변경 5·근거 없음 5), SC-015 미확보 분야 3/자치구 3의 문의 6건. 문항 공유 가능하되 기준별 결과 기록.
- 복합 문의 2건: 알려진 것은 순차 안내, 미해결만 이관 대상으로 보존, 전체 맥락은 전달. 중간 사람 요청 시 즉시 중단·요약.
- SC-018 4경로: 두 번 미확인/두 번째에 확인/첫 질문 후 사람 요청/제안 거절. 세 번째 같은 질문 0건.
- 명시 요청 4표현+버튼+1번 키 × 시작/확인/답변 중=18건. 텍스트 입력창의 숫자 1 입력이 연결을 유발하지 않는지도 확인.
- 무근거·타 구·만료·대체 claim·상충 연락처·위조 chunkId·잘못된 모델 형식은 사실 안내 차단. 개발 표본으로 맞춘 임계값을 독립 문항을 보고 재조정하지 않는다.

## 5. 전달·복구

- 요약 정정 후 예전 revision 승인 → 409, 최신 요약 승인 → 동일 handoff ID 한 번만 접수.
- confirm/skip 차이, 필드 미확인과 요약 미승인 구분, 전달 실패 재시도, 중복 commandId 결과 재사용 확인.
- LLM 지연 중 버튼 연결 → 상태 즉시 전환, 늦은 원 답변 재생 없음.
- 서버 재시작 후 큐·원문·승인 상태 복구, 진행 중 요청은 완료로 위장하지 않음.
- 시민 토큰으로 콘솔 호출·다른 세션 접근은 거절, 로그/응답/브라우저 번들에 API 키 없음.
- 실제 Chrome 마이크 거부·무음·한국어 STT/TTS를 수동 확인한다. 텍스트 E2E로 음성 성공을 대체 주장하지 않는다.

## 6. 완료 보고

### 제출 배포와 피드백 검증

1. 보유 호스팅에서 Node 1개 replica, 지속 디스크 DATA_DIR, HTTPS·서버 환경변수·콘솔 인증을 준비한다. npm build 결과를 같은 버전으로 제출 주소에 기동한다. 서버리스 임시 파일시스템에 상담 스냅샷을 두지 않는다. 현재 실제 계정/URL이 확보되었다는 의미는 아니다.
2. 제출 URL의 시민/인증 콘솔을 서로 다른 브라우저 세션으로 열고 마이크·텍스트·자료 버전·전달 상태·새로고침·프로세스 재시작 복구를 확인한다. localhost 결과와 배포 결과를 별도 기록한다.
3. 일반 불만은 요약 승인, 매우 불만+명시 연결/제안 수락과 명시 생략은 unconfirmed+사유, 무응답은 자동 승인 안 됨을 확인한다. 기존 수도 회귀는 일반 불만이라 그대로 유지한다.
4. 연결 버튼 가시성, 중립 확인 카드, 항목별 확인/미확인, 한 필드 수정, queued 30초 경과 안내와 전송 실패 재시도를 확인한다. 전체 대화는 접기/펼치기로, 완료 상담은 같은 콘솔 필터로 확인한다.
5. 단순 문의 1건의 안내 완료 확인, 미확인 종료 1건, 이관·담당 claim·complete_case를 포함하는 모의 상담 묶음을 만들고 /console/metrics 보고서를 원 이벤트와 대조한다. 처리량은 관찰 기간과 함께, 평균은 완료 표본 수와 함께, 분모 0은 null로 표시한다.
6. 개선 후보 1건이 승인 전 검색에 나타나지 않는지, 원문 검증·승인·기존 회귀 통과 후 새 corpus에서 해당 새 질문에 답하는지 확인한다. 기본 수도 회귀 corpus와 별도로 실행한다.

SC-019~023도 필수 증거에 포함한다. 실제 상담사 인터뷰·생산성 전후 비교는 후속 파일럿이며 이번 모의 검증으로 대체 주장하지 않는다.

SC-001~010·012~013·015~023의 증거, 데이터 검증 수/제외 수·corpusVersion, 실제 모델 ID, 미통과 시험과 백업 위치를 기록한다. SC-011 성능 표본·SC-014 신규 분야 확장 시험은 후순위로 미실행 여부를 명시한다. 영상은 기능 증거의 백업이며 자유 문의 동작을 대신하지 않는다.
