## Summary

서울시·25개 자치구 생활행정 전반의 자유 문의를 접수하고, 검증된 근거로 안내할 수 있는 항목은 하나씩 안내한 뒤 미해결 항목을 확인 요약과 함께 상담사 콘솔로 전달한다. 세 시연은 회귀 기준이며 고정 응답 목록이 아니다.

Next.js 단일 TypeScript 앱으로 시민 화면·콘솔·서버를 묶는다. 한국어 브라우저 음성 기능과 텍스트 대체 입력을 제공한다. 자료는 로컬 Markdown과 정규화한 색인으로 관리하고, 관할·유효성 필터 후 소규모 검색을 수행한다. LLM은 해석·근거 기반 답변·요약의 후보만 만들고 서버가 이관·상태·출처를 검증한다.

데이터 수집의 핵심은 기존 36건 재사용 → 시연 핵심 6건과 대체 관계 검증 → 일반 문의에 쓸 기존 자료 추가 검증 → 자료·정답표 동결이다. 전 분야를 수집하지 않아도 문의 접수·근거 부족 처리·사람 연결은 전 분야에 적용한다. [수집 절차](data-collection.md)를 AI 담당 1의 실행 기준으로 삼는다.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 22 LTS 이상 중 팀 환경에서 사전 확인된 버전. 설치 시 정확한 버전을 lockfile에 고정.
**Primary Dependencies**: Next.js App Router 16.x, React 19.x, Zod, gray-matter, Vitest, Playwright. LLM 호출은 서버의 OpenAI Responses REST 어댑터 한 곳에 격리하며 모델 ID는 환경변수로 지정한다.
**Storage**: 단일 장기 실행 Node 프로세스의 상담 Map + 서버 전용 JSON 스냅샷(원자적 임시 파일 교체). 근거는 Markdown + 정규화 색인. 벡터 DB·별도 Python 서비스 없음.
**Testing**: Vitest로 정책·검색·계약·재시도·정답표 검증, Playwright로 두 화면 텍스트 E2E, 실제 Chrome 음성 수동 검증.
**Target Platform**: Chrome 최신 안정판, 제출 HTTPS 주소의 단일 장기 실행 Node 서버(1 replica)와 지속 디스크. localhost는 개발·현장 백업용이며 제출 배포 검증을 대신하지 않는다.
**Project Type**: 두 화면과 내부 HTTP 인터페이스를 가진 웹 앱.
**Performance Goals**: 콘솔 1초 polling. SC-011의 응답 시작 p95 5초·수신 후 표시 2초는 후순위 측정 목표이지 검증 완료 성과가 아니다.
**Constraints**: 남은 290분·4인, 실제 전화망/개인 조회/자동 부서 전송 없음. 인터넷은 LLM·초기 자료 수집에 필요하며 상담 중 웹 검색은 금지.
**Scale/Scope**: 초기 36문서, 답변 가능 문서는 검증 통과분만, 두 화면·시연용 동시 5세션 목표. 서울 전 분야의 정답률 보장이 아니라 접수·근거 판정·이관 범위를 보장.

## Phase 1 — Design and Contracts

지역은 문의 항목의 배출지·발생지·거주지 목적별로 저장하고 발화 근거와 확인 상태를 보존한다. 검색에는 현재 목적의 관할만 전달한다. 기존 정보 재사용·서로 다른 지역·정정 후 재검색은 SC-025로 검증하며 필수 정보 두 번 한도는 유지한다. 새로운 서비스나 작업을 늘리지 않고 기존 추출·검색·검증 task에 통합한다.

인계 후 시민 화면은 queued 동안 대기를 표시하고, 상담사의 claim 수락 시 ‘상담사 연결 완료’ 최종 화면으로 끝난다. 시연 표기를 유지하며 이후 complete_case·transfer_demo 결과는 콘솔/지표에만 반영한다. 시민 대화 입력·후속 처리 결과 표시는 구현하지 않는다. 향후 양방향 문자 상담은 sessionId/handoffId를 참조하는 별도 메시지 모듈로 추가하며, 현재 AI 원문과 상태/계측은 그대로 보존한다. 메시지 저장·송수신 API·채팅 UI는 이번 구현에 넣지 않는다.

[data-model.md](data-model.md), [contracts/service.md](contracts/service.md), [quickstart.md](quickstart.md)로 상태·HTTP·판정·두 화면·검증을 고정한다. 수집 데이터는 [data-collection.md](data-collection.md)의 정규화 규칙을 따른다. 운영 시점은 Asia/Seoul이며 시연 fixture만 기준월을 2026-11로 고정한다.

## 남은 4시간 50분의 분담과 통합

아래 단계표는 작업 초점이며 전체 단계가 끝날 때까지 다른 담당자가 대기하는 순서가 아니다. 공통 타입 이후 FE는 화면 fixture·음성, AI1은 원문 검증·검색, AI2는 해석·요약을 진행하고 AI3는 저장·인증·API를 병행한다. live 통합에 실제로 필요한 선행 조건만 유지한다. 같은 담당자의 작업은 겹치지 않는다.

tasks.md의 단축 작업 예산은 FE 165분·AI1 165분·AI2 160분·AI3 230분, 합계 720인·분이다. 기존 자료·공통 코드·AI 보조 재사용을 전제로 한 목표치이며 실측 소요시간이나 범위 축소가 아니다. 작업 순서와 담당자 자원을 함께 반영한 예시 일정은 첫 이관 API 2시간 40분, 화면 포함 검증 3시간 10분, 최종 제출/검증/녹화 확인 4시간 25분이다. 최신 가용 290분에서 265분 목표를 제외한 여유는 25분이다. 오류 수정·배포/네트워크 지연을 이 범위에서 처리하며, 6시간 예산에서 계산한 이전 여유는 폐기한다. 정확한 task별 시작/종료는 tasks.md의 4인 병렬 실행 일정을 따른다.

요약 전달 후 시민이 정정하면 같은 handoffId로 수정본을 재전달한다. 수락 전 정정은 변경 부분 재확인(기존 생략 조건 유지) 후 최신 요약·변경 표시·이전 이력을 갱신하고 중복 대기열을 만들지 않는다. 수락과 경합하면 정정문을 보존해 콘솔에 알리며 시민의 최종 연결 완료 화면은 유지한다. 이 경로는 FR-039·SC-026과 기존 정정/전달/재시도 task에 포함한다.

## Reliability, Privacy and Exit Gates

- 세션별 명령은 직렬 적용, revision으로 충돌 검출. LLM 호출 중에도 연결 이벤트를 별도 처리하고 늦은 답변은 무시한다.
- 모델 요청 제한 10초, 형식 복구 재시도 최대 1회. 실패 시 고정 사실 답변 대신 오류·사람 연결 경로 제공. 연결 요약은 실패 시 대화 기반 단순 요약 초안으로도 확인 가능하다.
- 기본 경로는 요약 확인, 매우 불만+연결 의사 확인 시 또는 명시적 생략 요청 시에는 confirmation=unconfirmed와 skipReason을 저장해 낭독·승인 없이 전달한다. 무응답만으로 생략하지 않는다. 요약 확인 무응답 30초 후 “확인 없이 전달” 버튼을 표시하고 자동 승인하지 않는다. 마이크 무음은 처리 완료로 세지 않는다.
- 가상 자료만 사용하는 제출 데모이며 서버 키는 브라우저에 전달하지 않음. 세션 접근은 별도 시민/콘솔 토큰, 콘솔 토큰은 Authorization 헤더. 토큰·원문은 일반 로그에 남기지 않음. 스냅샷은 Git 제외·재시작 복구용이며 시연 후 삭제 절차는 별도 사용자 실행.
- 로그는 requestId·sessionId·지연·근거 ID·정책 사유·검증 실패 코드만. 세션 최대 5개, 동일 세션 중복 요청은 409/429와 재시도 안내.
- 근거는 서버에서 source URL과 검증 claim을 바탕으로 생성한다. 문서 ID가 존재해도 다른 조건의 숫자·날짜·담당을 끌어오면 차단한다. 미검증·타 구·미래 시행·상충 claim은 답변용 후보에서 제외한다.
- 무근거 답변·이전 정책 오안내·명시 연결 차단·요약 미확인 오표시는 배포 중단 사유. 키·네트워크가 없으면 fixture 화면 개발과 녹화 백업은 가능하지만 실제 AI 기능 완료로 보고하지 않는다.
- 이번 단계는 계획·설계 문서만 작성했다. 앱·수집기·테스트·새 자료 수집은 아직 실행하지 않았다.

## Feedback Implementation Gates

- 배포: 기존 보유 계정의 단일 VM 또는 장기 실행 Node 호스팅에 1개 인스턴스로 배포한다. HTTPS와 지속 디스크(DATA_DIR)를 사용하고 PM2 등으로 동일 프로세스를 재시작한다. 실제 호스팅 구매·계정 생성·배포는 별도 구현 작업이며 이번에는 하지 않는다. 계정·URL·디스크 미확보 시 제출 검증 차단 사항으로 즉시 보고한다. 메모리를 공유하지 않는 서버리스는 이 계획의 대체 배포가 아니다.
- 30분 내 배포 가능성·키·모델 사전 시험, 3.5시간 내 제출 환경 첫 통합, 마지막 1시간에 제출 URL로 두 브라우저·음성·인증·재시작 검증. HTTPS 프록시 뒤 앱은 단일 로컬 포트로 전달하고 비밀키/지속 디스크 파일을 공개 정적 경로에 놓지 않는다.
- 개선 루프 최소 구현: AI3가 이관 완료 시 비식별 처리 결과·근거 부족 사유를 기록하는 한 동작과 개선 후보 목록/JSON 내보내기를 제공한다. AI1은 후보 1건의 공식 근거를 검증하고 AI2는 회귀·새 질문을 확인한다. 승인 후 별도 corpus 버전에 수동 반영한다. 자동 재학습·자동 크롤링·관리자 대시보드는 만들지 않는다.
- 상담사 부담: 명시적 연결 전에는 근거 있는 짧은 답변과 안내 완료/추가 도움 경로를 제공한다. 연결 요청 이후 AI 안내로 돌려보내지 않는다. 상담사가 claim/complete_case를 눌렀을 때 시작/종료 시각과 가명 담당 ID를 기록한다. 최소 모의 지표는 JSON 보고서로 산출하고 별도 통계 화면은 후순위다.
- AI 안내 완료율과 이관율은 같은 관찰 구간의 종료된 세션 집합을 분모로 하고 그 집합 안의 ai_confirmed/handoff만 각각 분자로 센다. session_ended 이벤트 기준 세션당 1회 집계하고 대기·진행 중은 분모/분자에서 제외해 별도로 표시한다. 안내 완료는 실제 행정 처리 완료가 아니다. 원인별 이관 건수와 명시 요청 건수를 분리한다.
- 상담사 처리량은 담당자별 명시 완료 건수와 관찰 시간, 처리 시간은 claim~complete_case의 완료 건 평균/표본 수로 제시한다. 미완료 건은 평균에서 제외해 별도 표시하고, 대기는 receivedAt~claim이다. 단일 상담 중복 claim 금지. 모의 데이터로 업무 증가·감소를 입증했다고 주장하지 않는다.
- 추가 수집 범위 확대 대신 개선 1건 시험을 우선한다. 프런트는 별도 완료 상담 화면 없이 같은 콘솔의 완료 필터와 전체 대화 접기를 사용하고, 연결 버튼·확인/미확인 구분·부분 수정에 집중한다.
- 후속 파일럿: 실제 상담사 동의 하에 요약·근거 카드 유용성 평가와 동일 관찰 기간의 기존 방식 대비 재설명/처리 시간/처리량을 비교한다. 외부 연락·실제 상담 자료 수집은 이번 요청 범위가 아니다.

추가 서비스·벡터 DB·자동 크롤러·다중 에이전트 런타임을 도입하지 않는다. 역할은 개발자 분담이며 제품에서 세 에이전트를 병렬 실행한다는 의미가 아니다.

## Task Refinement Decisions

공용 콘솔 토큰은 한 명의 가상 상담사 CONSOLE_AGENT_ID에 매핑한다. 별도 다중 상담사 로그인은 만들지 않으며 보고서는 단일 모의 담당자임을 명시한다. Handoff와 Session 완료/실패 상태를 모델 계약대로 함께 기록하고 후보 없음 사유는 RoutingResult에 담는다. 태스크 시간/담당/51개 ID는 유지하며 상세 지표·정정 경합 검증은 기존 테스트에 포함한다.
