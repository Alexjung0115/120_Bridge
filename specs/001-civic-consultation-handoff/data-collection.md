# 데이터 수집·검증·동결 계획

담당: AI1. AI2는 문서가 답할 수 있는 질문을 검토하고 AI3는 정규화 검증기를 맡는다. 문서 수보다 질문을 근거로 처리할 수 있는지를 평가한다.

## 1. 범위와 완료 조건

- 접수: 서울 생활행정 전반. 직접 답변: 검증된 자료의 유효한 내용만.
- 시작점: rag-data/index.json 36건(폐기물 8·주정차 11·정책 변경 7·부서 10), verified=true 6건·false 30건.
- 자료 감사 기준 원문 URL은 32개이며 구별 자료는 강남·마포·관악·강동·금천 5개 구에 한정된다. 동일 원문을 다른 분류로 수록한 레코드는 별도 독립 근거로 중복 집계하지 않고 sourceUrl·contentHash로 연결한다. 25개 자치구 자료가 확보된 것으로 표시하지 않는다.
- 필수: 시연 핵심 6건의 인용 항목·창구 근거·두 대체 관계를 우선 대조. 일반 질문은 같은 문서의 다른 품목/절차도 활용한다.
- 추가 목표: 기존 30건 중 다른 자치구·주정차·업무분장 4–6건 원문 검증. 목표 건수 미달 자체보다 독립 질문 시험에서 필요한 검증 근거 부족이 완료 판단 기준이다.
- 신규 분야 문서 수집은 여유 시 2–3건에 한정. 전 자치구·전 분야 문서 확보, 비공개 120 상담자료 접근, 시민 개인정보 수집은 하지 않는다.

## 2. 출처 우선순위와 발견 방법

| 우선순위 | 출처·방법 | 수집 내용 |
| --- | --- | --- |
| P0 | 기존 index의 공식 URL을 직접 열기 | 시연 인용 조건·금액·기한·창구 및 확인일 |
| P1 | 자치구 공식 분야별 안내·조직도, 서울시 분야별 안내·공고 | 관할별 절차·신청 창구·담당 업무 |
| P1 | 정책 담당 기관 Q&A와 공식 접수기관 | 일반 정책과 개인 처리 창구 구분 |
| P2 | 서울 열린데이터광장·정보소통광장에서 주제/업무명 검색 | 공개 구조화 목록·공고 후보, 개별 원문을 다시 검증 |
| 제외 | 검색 요약·블로그·LLM 생성 문장·원문 미열람 수집 요약 | 후보 발견만 허용, 답변 근거 승격 금지 |

예시 발견 질의: “site:mapo.go.kr 대형폐기물 배출”, “site:seoul.go.kr 주정차 신고”, “기관명 부서명 업무분장”. 검색 결과 순위는 공식 권한·최신성 판단 근거가 아니다. 제휴 운영 사이트는 공식 기관에서 연결한 URL인지 확인한다.

## 4. 수집 파이프라인

1. manifest에 docId·원 URL·주제·목적(답변/창구/변경 이력)·담당자를 등록한다. 기존 상대 path를 안정적인 docId로 유지한다.
2. 공개 URL을 허용 목록으로 가져온다. HTTPS만, 비공개 IP·localhost·redirect 후 비허용 호스트 차단. 자동 수집은 호스트별 1개 동시 요청·요청 간 1초·실패 재시도 1회, robots/이용 조건과 재배포 표시 확인.
3. HTML은 본문과 표 머리글을 보존한다. PDF는 pypdf 등으로 추출하고 금액·날짜 표는 화면과 대조한다. 스캔/OCR이 필요한 자료는 이번 수집에서 보류한다.
4. 원본 HTML/PDF는 data/sources/<docId-safe>/<retrievedAt>/에 내부 보관하고 contentHash·원 URL·공고 번호를 기록한다. 전체 원문 공개 재배포 대신 필요한 발췌와 출처를 제공한다.
5. Markdown 정리본과 발췌를 생성한다. LLM이 초안을 정리할 수 있으나 verified 상태를 자동 부여하지 않는다. 시민·문서 속 명령문은 데이터일 뿐 실행 지시로 취급하지 않는다.
6. AI1이 원문과 날짜·수치·대상·제외 조건·신청 경로를 대조하고 evidenceLog에 확인 문단·항목·불확실성을 남긴다. AI2가 시연 핵심 사실과 정책 대체 두 쌍을 교차 검토한다.
7. 검증기를 통과한 청크만 answerEligible=true. 창구 업무분장은 routingEligible를 별도 판정한다. 오래된 일정과 미변경 부서 정보를 같은 상태로 처리하지 않는다.
8. 색인을 빌드하고 corpusVersion·hash·검증 건수·배경 전용 건수·제외 사유를 기록한다. 앱은 지정 버전을 시작 시 로딩하며 상담 중 무제한 다운로드하지 않는다.

## 5. 정규화 계약

기존 front matter와 index를 동시에 수동 편집하지 않는다. 이행 중에는 기존 index를 입력으로 읽고 정리본과 교차 검사해 data/normalized/corpus.json을 생성한다. 충돌 시 실패 보고 후 한 곳을 바로잡는다.

- 필수: docId, sourcePath, title, category, sourceUrl, retrievedAt, verificationStatus, jurisdiction, chunks.
- 날짜: publishedAt/updatedAt/effectiveFrom/effectiveUntil/sourceVerifiedAt를 분리. 모르면 null, 이유는 dateStatus에 기록. 기존 effective_date는 date_basis가 시행일일 때만 effectiveFrom으로 옮긴다.
- 기존 source_verified 문자열에서는 ISO 날짜만 sourceVerifiedAt로 분리하되 과거 확인 기록이다. verified=true만으로 모든 문단의 사실을 무조건 허용하지 않는다.
- jurisdiction: scope=city|district|national|organization|unknown, districtCode/name, applicableDistricts. “120다산콜재단”을 자치구로 해석하지 않는다. 기관 창구와 적용 지역은 별개다.
- 청크: chunkId, heading, text, claimKeys, verifiedClaims, answerEligible, routingEligible, conflicts. 금액은 규격·단위와 함께, 표는 머리글+행을 함께 보존한다.
- 변경: predecessorDocId, successorDocId, claimKey, before/after, validFrom, validUntil, evidenceChunkIds. 기후동행카드 종료 일정과 페이백 신청·입금 시기의 두 관계를 명시한다.
- 검증 로그: reviewer, reviewedAt, sourceHash, checkedClaims, unresolvedConflicts. sourceVerifiedAt는 근거 기준일이나 시행일을 대신하지 않는다.

## 6. 알려진 충돌 처리

- 평화환경 전화번호 두 값은 conflicting claim으로 표시하고 시민 안내에서 제외. 확인된 1599-0903 등 다른 번호까지 일괄 차단하지 않는다.
- 냉장고 비용은 용량 미확인 상태에서 8천 원으로 확정 금지. 300/500리터 경계와 업소용 조건을 원문 표로 확인한다.
- 머리글과 값 개수가 다른 요금 표는 해당 수치 청크 제외. 원문 재검증 전 추정 배치 금지.
- 주정차 신고 기한은 자치구·신고제도별 적용 범위를 확인한다. 서울시와 금천 값을 전역 우선순위로 합치지 않는다.
- 법령 요지는 원문 조문으로 표시하지 않는다. 현재 시행본을 원문 확인하지 못하면 확정 법률 안내 근거에서 제외.
- 기존 도로교통법 제160조 레코드의 2027-04-14 표시는 미래 시행본 여부를 확인해야 한다. 2026-11 시연에서 이를 현행 규정으로 사용하지 않는다. 메타데이터의 날짜 오류인지 실제 미래 시행본인지 원문에서 확인하기 전 해당 청크를 격리한다.
- 일반 전환일 9월 1일과 후불카드 이용 종료 9월 30일·일반 교통카드 전환 10월 1일은 서로 다른 적용 대상이다. 상품 유형과 claimKey를 분리하고 하나의 전환일로 덮어쓰지 않는다.
- 정책 이전 문서는 일정 claim만 대체하고 별도 확인된 업무 주관 정보는 routing 근거로 유지할 수 있다. Q&A 운영 부서를 실제 정책 주관 부서로 오인하지 않는다.

## 7. 검색용 청크와 평가

문단/소제목 단위 약 300–800자, 긴 문단만 분할하며 표 행은 머리글과 함께 유지한다. 같은 문서끼리 중복을 제거하고 상위 결과가 한 문서로만 채워지지 않도록 최대 2청크/문서로 시작한다. 필요한 인용 범위가 잘리면 관련 청크를 명시적으로 추가한다.

개발용 질문과 독립 평가 질문을 분리한다. AI2가 SC-013 15문항을 만들고 AI1은 인용 가능한 근거·없는 근거만 표시한다. SC-015의 없는 분야/없는 구 표본 6건, SC-016 복합 2건, SC-018 질문 한도 4건은 겹칠 수 있으나 각 기준의 결과를 별도로 기록한다. 정답표가 수집한 사실과 다르면 사실을 조작하지 말고 충돌을 보고하고 시험 자료 버전을 분리한다.

## 8. 산출물과 중단 기준

피드백 반영 개선 루프는 별도 대량 수집을 추가하지 않고 다음 1건 시험으로 수행한다: 근거 부족 이관 → 상담사 모의 처리 결과 기록 → 비식별 후보 → 공식 URL 발견·원문 발췌 확인 → AI1 검증 및 AI2 검토 승인 → 별도 시험 corpus 빌드 → 기존 회귀와 새 질문 통과 → publishedCorpusVersion 기록. 원 상담을 임의로 해결 완료 처리하거나 정답 문장을 그대로 검색 자료에 넣지 않는다. 개선 후보에는 검증 전 답변 자격이 없다. 시연용 기본 corpus는 유지해 수도 근거 없음 회귀와 개선 후 자료 버전을 각각 시험한다.

구현할 산출물: source-manifest.json, evidence-log.jsonl, normalized/corpus.json, retrieval-calibration.json, tests/fixtures/generalization.json, validation-report.json. 이 문서 작성만으로 해당 파일이나 수집 결과가 생성된 것은 아니다.

수집 중단 기준은 3.5시간 동결 또는 핵심 근거+일반 질문 시험에 충분한 검증 자료 확보다. 나머지 30건을 무조건 모두 검증하려 하지 않는다. 불확실한 자료는 배경/격리 상태로 남기고 접수·이관 기능으로 범위를 보완한다.

후속 운영은 변경 hash 감지 → 재검토 대기 → 새 버전 승인 → 평가 통과 → 버전 교체의 순서로 확장한다. 자동 감지만으로 답변 근거를 승격하지 않는다.
